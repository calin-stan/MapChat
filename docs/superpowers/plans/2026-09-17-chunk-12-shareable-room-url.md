# Chunk 12: Shareable Room URL and Polish Implementation Plan

**Review feedback:** [2026-09-17-chunk-12-shareable-room-url-feedback.md](2026-09-17-chunk-12-shareable-room-url-feedback.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/room/<id>` opens the map centred on that room with its panel open; the address bar follows the open room without navigating; an address that names no room answers 404 with a way back; a room that disappears while open closes its panel with a page-level notice.

**Architecture:** A new server page `src/app/room/[id]/page.tsx` loads the room with a small server-only function and renders the existing `MapShell` with `initialSelection: { kind: "room", room }`, the room as centre and `ROOM_ZOOM`; a missing or malformed id calls `notFound()`, rendered by a root `not-found.tsx`. `MapShell` gains one hook, `useSelectionUrl`, that mirrors the selection into the address with `history.replaceState` (no history entries, no navigation). `RoomPanel` reports a terminal 404 through a new optional `onGone(room)`; `MapShell` turns it into a `roomGone` action, and the pure `selectionReducer` answers with `{ kind: "none", gone: room }`, which the shell renders as a dismissible notice above the greeting.

**Tech Stack:** TypeScript 5 (`strict`), Next.js 16.3.5 App Router (Turbopack), React 19.2.8, Tailwind CSS 4, shadcn/ui (style `base-nova`, Base UI), `react-icons`, `@supabase/supabase-js` 2, zod 4, Vitest 5 with jsdom 30 and Testing Library, `@playwright/test` 1.63 on chunk 9's harness (Chromium only), pnpm 10, Node 22.

**Spec:** `docs/superpowers/specs/2026-09-16-map-chat-implementation-chunks.md` §0 and "Chunk 12" (**Spec needed: no**), argued from `docs/PRD.md` §3 (last paragraph: "Rooms are addressable by URL, `/room/<room-id>` … Opening that URL shows the map centred on the room with its panel open") and §6.5 (`GET /api/rooms/:id`). ## Design decisions

The chunks document's chunk 12 section is short and partly superseded. These are the points where this plan pins something down or departs from its wording.

1. **No shell extraction, no pin-fetch alert.** Both are already settled by map-shell design §1. The route is the only new page.
2. **The data function is `loadSharedRoom(id)` in `src/lib/page/sharedRoom.ts`**, `server-only`. A malformed id returns `null` without touching the database, so the page answers 404 for it (a page has no 400; the API route keeps its 400). A repository failure throws; it is never reported as a missing room.
3. **The page relies on Next's default for dynamic segments**: without `generateStaticParams` a `[id]` page is rendered per request (`ƒ` in the build output). No `export const dynamic`, no `loading.tsx` in the segment: the await happens before anything streams, which is what makes `notFound()` answer with a real 404 status (not-found.md: "200 for streamed responses, 404 for non-streamed").
4. **One root `src/app/not-found.tsx`** serves both `notFound()` from the room page and any unmatched URL, with neutral copy. It reuses `PanelFrame` on an empty page. It exports `NOT_FOUND_TEXT` for its test; the prototype build accepts the extra export on a `not-found` file. **No `error.tsx`**: a database failure while opening a shared URL shows Next's default error page. That is outside the chunk's listed error surfaces and recorded as a known limitation (Task 5).
5. **The address is a pure function of the selection**: `pathForSelection` → `/room/<id>` for a room, `/` for everything else (nothing, a draft, the gone-room notice). `useSelectionUrl` applies it in an effect keyed on the path string and skips the call when the address already matches, so loading `/room/<id>` never rewrites it. Created rooms and 409 hand-offs get their address through the same effect, with no code of their own (new-room design §12 deferred exactly this to chunk 12).
6. **`replaceState`, as the chunks document says**: no history entries. Back leaves the app instead of stepping through rooms; the tab title stays "Map Chat"; the address carries no map position. All three are recorded as known limitations, not built.
7. **The gone-room notice is part of the selection**: `{ kind: "none"; gone?: Room }`, produced only by a new `roomGone` action for the room that is open. Every other action already builds a fresh selection, so opening another room, placing a draft, closing or dismissing clears the notice without any extra state or effect. `roomGone` for a room that is not open returns the same state object (nothing re-renders), which makes a late report harmless. `handoffReducer` passes the action through and keeps the revision.
8. **`RoomPanel.onGone?(room)` is optional and reports once per terminal feed.** With it, the shell closes the panel; without it (the dev-only layout fixture, component tests) the chunk 9 hint stays. An effect uses a ref guard so changed callback/room identities cannot report twice. Absence of a callback does not consume the notification: supplying it later reports once. A one-frame flash of the in-panel hint before the shell closes the panel is acceptable (it says the same thing).
9. **On `roomGone` the shell also calls `pins.refresh()`**, so the dead room's pin goes with the next viewport answer instead of waiting for the 30 s tick.
10. **The notice lives in the panel slot, above the greeting** (`RoomGoneNotice` in `src/components/panel/`), built like `MovedNotice`. `PanelSlot` gains `gap-2`; it has exactly one child in every other state, so nothing else moves.
11. **`openRoom` stays on the pin path.** Room-panel design §8 says chunk 12 *may* switch the helper to `/room/<id>`; this plan does not, because every clock-sensitive scenario of chunks 9–11 is tuned around the world-view load, and the pin path would otherwise lose its only e2e coverage. The shared URL gets its own spec instead.
12. **One network interception in e2e.** The API has no delete endpoint, so scenario 6 makes one room's messages endpoint answer 404 with `page.route`, the same kind of stand-in as chunk 11's `refuseRealtime`. The page itself still loads from the real server. Everything else uses the real API.
13. **Shell tests go into `MapShell.test.tsx`** (mocked `useRoomPins`, real panel, scripted messages API): its mock set is exactly what the address and gone-room cases need. `MapShell.newRoom.test.tsx` gets two one-line address assertions in existing cases. jsdom's `window.location` persists across tests in a file, so `MapShell.test.tsx` resets it in `afterEach`.

Create `src/lib/page/sharedRoom.ts`:

```ts
import "server-only";

import { findRoomById } from "@/lib/db/rooms";
import { uuidSchema } from "@/lib/schemas/query";
import type { Room } from "@/lib/schemas/types";
import { createServiceClient } from "@/lib/supabase/server";

/**
 * The room behind a shared `/room/<id>` URL (PRD 3), or null when the address
 * names no room: an id that is not a UUID never reaches the database. A
 * database failure throws `RepositoryError`; it is not a missing room.
 */
export async function loadSharedRoom(id: string): Promise<Room | null> {
  const parsed = uuidSchema.safeParse(id);
  if (!parsed.success) return null;
  return findRoomById(createServiceClient(), parsed.data);
}
```

```ts
import { useEffect } from "react";

import type { Selection } from "@/lib/page/selection";

/** The address of a selection (PRD 3): an open room has its own URL, everything else is the map. */
export function pathForSelection(selection: Selection): string {
  return selection.kind === "room" ? `/room/${selection.room.id}` : "/";
}

/**
 * Keeps the address bar on the selection without navigating (chunk 12).
 * `replaceState` adds no history entry, so Back leaves the app instead of
 * stepping through rooms, and Next's router picks the new path up without
 * fetching or remounting anything. A reload then lands on `/room/<id>`, which
 * renders this same shell with the room open.
 */
export function useSelectionUrl(selection: Selection): void {
  const path = pathForSelection(selection);
  useEffect(() => {
    if (window.location.pathname !== path) window.history.replaceState(null, "", path);
  }, [path]);
}
```
